EasyControl / Documentation

A shorter path
to the other screen.

Build the app, connect directly, and understand what runs underneath. Start here.

Development software, not a production release. Real macOS capture and rendering have been observed, but real input validation and public distribution checks remain. There is no public signed installer yet.

EasyControl is a Rust remote-desktop engine with a Tauri 2, React and TypeScript interface. The desktop currently targets direct LAN sessions using a numeric IP address and port, SPAKE2 password authentication and encrypted protocol v5 traffic.

The application source repository currently requires access. Build commands below assume you have access to the application repository. The website repository is public. Contact Udhay Bhat for application access.

Build for macOS

Use Rust stable, Node.js 20+ with npm, and the native tools required by Tauri. Optimized builds are recommended for real frame-throughput testing.

  • macOS with Xcode Command Line Tools.
  • Rust stable, Cargo, rustfmt and Clippy.
  • Node.js 20 or newer and npm.
  • Access to the EasyControl application repository.

For current toolchain setup, use the official Tauri prerequisites and Rust installation guide.

Terminal · clone and install 
git clone https://github.com/udhaybhat00/easycontrol.git
cd easycontrol/desktop
npm ci
npm run tauri:dev

Create an optimized app and DMG

Terminal · from easycontrol/desktop 
npm run tauri:build

Artifacts are written under desktop/src-tauri/target/release/bundle/. The app is in macos/ and the disk image in dmg/. Architecture-specific filenames depend on the build target.

Local signing is different from distribution. Ad-hoc builds can need fresh macOS grants after replacement. Use the same Apple Development signing identity through APPLE_SIGNING_IDENTITY for repeat local testing. Public distribution still needs Developer ID signing, notarization and installation testing on a clean Mac. Keep signing credentials out of source control.

Isolated same-Mac QA client

The QA profile has a separate application name, bundle identifier and storage namespace. It reuses the same Rust core and frontend.

Terminal · from easycontrol/desktop 
npm run tauri:build -- --bundles app \
  --config src-tauri/tauri.qa.conf.json

Do not distribute the QA app as a production artifact. Keep input disabled during recursive same-Mac capture unless a controlled target and explicit host approval are in place.

macOS permissions

Open System Settings → Privacy & Security and grant access to the exact installed host app. EasyControl uses supported OS APIs and never bypasses these controls.

Permission When needed
Screen Recording On the host, before actual screen capture. Quit and reopen the app after granting it.
Accessibility On the host, before approved mouse or keyboard injection.
Input Monitoring Not required by the current backend; EasyControl does not observe global keystrokes.

The desktop Settings page reports these grants. A QA client that only views frames does not need host capture/input permissions. If the QA app hosts, its grants are separate.

A listening socket is not proof that screen capture is authorized. Check actual sharing status and rendered application content. Wallpaper-only frames from stale grants are not a successful capture test.

Your first direct session

  1. Start on the host. Open Home → Share this computer. Use port 5899 unless you need another port in 1024–65535.
  2. Share credentials carefully. Start the host, copy its displayed LAN endpoint and share the session password with the intended person through a trusted channel.
  3. Connect on the client. Enter the host’s numeric IP address and port, then its password. The interface keeps passwords out of saved devices and history.
  4. Check the screen. The authenticated connection begins view-only. Screen Recording must be granted on the host for real frames.
  5. Approve only when appropriate. The host’s Approve control action enables its input backend. The client must also enable sending input. The host can revoke it at any time.
  6. End the session. Disconnect from either side. The host returns to stopped after the session ends; start it again for a new session.

For an isolated same-Mac QA client, use 127.0.0.1:5899. That loopback address does not connect to a different computer. Between machines, use the host’s real LAN endpoint and a reachable network path.

No cloud device-ID service, discovery or automatic NAT traversal is provided. Avoid exposing a development host directly to the internet.

Security model

Authentication and encryption run in Rust. The frontend controls the session API and does not implement a parallel networking stack.

  • Authentication: SPAKE2 with encrypted key confirmation.
  • Session encryption: ChaCha20-Poly1305 with directional key material derived through HKDF-SHA256.
  • Protocol: version 5, with bounded message/decompression handling.
  • Host authority: desktop input starts denied; approval and revocation are enforced by the host.
  • Frame isolation: bounded latest-frame delivery is scoped to the active authenticated session.
  • Local storage: saved addresses, devices, history and appearance; no persisted session passwords.
  • No public frame endpoint: native binary IPC connects Rust to the viewer.

Encryption is not a completed security audit. Independent review, real input denial tests and distribution validation remain release requirements. Unattended or high-risk deployment is not recommended at this stage.

Report a sensitive issue privately to the maintainer through GitHub before publishing exploit details. Do not attach session credentials, clipboard contents or private captured screens.

One engine. A thin desktop shell.

React + TypeScript · dashboard and viewer
↕
Tauri commands / events · bounded binary frame IPC
↕
Rust · SessionManager / SessionHandle / protocol v5
↕
OS capture + input · authenticated TCP transport

The viewer decodes actual RGBA frames and maps input into monitor coordinate bounds. Frame queues stay bounded; unread frames can be replaced when the viewer falls behind. Core features for capture, input, compression and crypto are selected with Cargo feature flags.

The repository also contains relay, clipboard and file-transfer core modules. They are not a claim of deployed cloud infrastructure or complete desktop UI workflows.

Troubleshooting

Host cannot bind the listening port+

Stop any stale EasyControl host and check whether another service owns port 5899. Use a different available port in 1024–65535 if necessary. Do not terminate unrelated processes. Port 5900 is conventionally used by VNC/macOS Screen Sharing.

Connection refused, timeout or wrong password+

Confirm the host is listening, the IP and port match the displayed endpoint, and both machines have a reachable network path. A handshake MAC mismatch can indicate the wrong password. A rejected password should leave the host available for a correct retry.

Authenticated, but no frames or only wallpaper+

Check the exact installed host’s Screen Recording grant. Replaced/ad-hoc-signed copies can have stale permission entries. Quit and reopen after granting access. Never count wallpaper-only output as a successful desktop capture.

Screen visible, but input does nothing+

Confirm Accessibility is granted to the host, the host explicitly approved control, and the client enabled Send input. Focus the viewer canvas. A client checkbox alone cannot grant host permissions. Real input testing remains a release gate.

The source link returns 404+

The application repository is private at present. Sign in with an account that has access, or contact the maintainer. The public website repository contains no application source or signing credentials.

Help test what’s next.

Useful contributions include reproducible bug reports, two-machine macOS test results, accessibility findings and focused fixes with regression tests. Preserve the working Rust engine and protocol behavior.

Include the app revision, OS version, steps to reproduce and expected versus observed behavior. Remove passwords, keys, personal addresses, private screenshots and clipboard content before sharing logs.
