This report separates actual macOS observations from mock tests and build results. The public source remains a development preview. Protocol v5, authentication, transport and cryptographic algorithms are unchanged.

## Confirmed defects and fixes

### Letter-key injection terminates the macOS host

Reproduction: start the installed host, authenticate the bounded loopback QA client, approve control, focus an unused address field, then send Shift + A using the existing v5 key commands. Mouse targeting and text insertion worked, but the host terminated when injecting a letter key.

The OS crash report showed SIGTRAP / EXC_BREAKPOINT on a Tokio worker. The stack passed through `_dispatch_assert_queue_fail`, `islGetInputSourceListWithAdditions`, `TSMGetInputSourceProperty`, Enigo's `keycode_to_string` / `get_layoutdependent_keycode`, and EasyControl input injection. This identifies a keyboard-layout API queue assertion, not an authentication or network failure.

Fix: translate existing printable physical-key wire codes to Apple's native ANSI keycodes on macOS. Enigo's `Key::Other` conversion uses these codes directly, avoiding its Unicode layout lookup on the worker. Special keys retain their existing mapping; Windows/Linux mapping is unchanged. Non-US layouts follow physical key positions on macOS. A regression enforces that every supported macOS letter, digit and punctuation key avoids the Unicode conversion path. The development-only QA client also has bounded runtime shutdown, avoiding a wait on its blocking stdin reader after peer disconnection.

Post-fix real key/revocation retesting is pending fresh host approval for the new session. A unit test and successful build alone do not close the OS crash regression.

### History never completes

Authenticated outgoing rows previously remained “Authenticated” after disconnection. The UI now completes the matching active history ID when the native status returns idle and records duration. Older entries without a recorded outcome or duration remain explicitly unknown; no historical outcomes are invented. Regressions cover isolation, repeat completion and clock changes.

### Monitor switching can overtake input release

Monitor selection previously called asynchronous key/button release without awaiting it. It now immediately stops forwarding new input while switching, waits for release enqueueing, then sends monitor selection. The async ordering regression also verifies that a failed release prevents the change. Physical multi-monitor validation remains outstanding.

### Ineffective settings

Removed disabled category tabs and clipboard/file-transfer permission switches for desktop workflows that are not provided. Added inline default-port validation. Host approval versus client “Send input” copy is distinct. Protocol implementations remain in the Rust core.

## Measured performance

These are actual same-Mac, optimized headless-client measurements taken during development checks, with other local build work possible. They are not a controlled idle-load benchmark. They exclude browser rendering, WebKit helpers, WindowServer and unrelated processes; they are not a cross-platform benchmark.

- 369 actual RGBA frames in 37.072 seconds: approximately 9.95 FPS.
- Frame dimensions: 2880 × 1800; 20,736,000 raw RGBA bytes per frame.
- Received raw frame bytes in that window: 7,651,584,000. This is decompressed frame payload, not network throughput.
- Client broadcast event lag: 0 in that window. End-to-end frame-drop counts and latency were not measured.
- Three process snapshots: native host CPU 64.0–70.9%, client 40.0–42.9%; host RSS 101,824–113,840 KiB, client 93,040–104,720 KiB.
- Loopback counter increase: 32,617,213 bytes over a 2.035-second sampling command window, approximately 15.3 MiB/s. Client bytes received match host bytes sent. This is a short sample, not a sustained bandwidth guarantee.
- The earlier debug QA client consumed substantially more CPU and received fewer frames. No production optimization was made on the basis of debug overhead.
